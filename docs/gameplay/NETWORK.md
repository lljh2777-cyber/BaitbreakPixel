# 0.25.6 双人联机（开发版）

本版已合入 feature/dev @ dfdd9af 的 NPC 觅食、社会反应、中钩及 QTE 修复。水域四种构图和材质仅用于本地小鱼视角，联机不发送这些选项或视觉种子，相关控件在联机期间禁用。

本文对应 0.25.6 源码及 watergen 本地 Windows 试玩包。双方使用同一份 BaitbreakPixel-0.25.6.zip，解压后运行；不要与旧版本混连。

抄网操作、模块及规则迁移见 [NET-ARCHITECTURE.md](../architecture/NET-ARCHITECTURE.md)。

0.21 加入更大水域与鱼镜头跟随，钩体与吊线在鱼咬钩前隐藏；0.22.0 在两类饵团共同吸动的基础上加入轻吸/猛吸取舍与入口反馈；0.22.1 增加吸食时游动减速；抄网点击统一转换成世界坐标。

鱼角色客户端只接收显式筛选的自身、环境和动作结果；隐藏钩分配、随机种子、生成真值日志与内部警惕数值不会发送给鱼客户端。房主仍掌握权威世界，这不防御恶意房主读取自己内存。

NPC 由房主模拟，两种客户端只接收 ID、位置、速度、朝向、外观与公共游动/真实中钩/提鱼动画，均不传 NPC 的随机源、目标、内部警惕、风险权重、饱食、进食计时或开发统计。岸边与观察视角继续使用原可见性限制，没有精确 NPC 图标。

当前双方必须使用 0.25.6，权威快照 schema 15，NPC 摄食和社会反应扩展字段采用严格校验，旧 0.25.0–0.25.2 快照不能直接恢复，钓鱼人公共投影 npc_profile_version=4，鱼端 npc_profile_version=2；另要求 authority bait_profile_version=3（鱼端饵型可见形态 guard 仍为 1）；缺失或未知版本拒绝恢复，不猜测旧存档的饵型。公开表现只携带合法的形状/气味/visual_kind，隐藏钩与内部倍率不发送。吸食减速由房主模拟，自由游动、慢游、冲刺和上钩后共用房间的吸食游速倍率。房主先在设置页保存玩法方案，再创建房间；双方准备前可通过“查看房主规则”查看全部选项与修改项。更换规则需离开并重新创建房间。长 QTE 使用自身捕获的时长及房主的历史输入核验，不沿用旧的 2.4 秒上限。鱼嘴默认在可食颗粒 10 px 内由房主自动判定咬食，基础每口容量 4，颗粒团/细条/块状最多分别 4/6/8 粒，冷却 0.80 秒；持续靠近会继续咬食，无咬食按键或网络命令。可咬食时优先于吸食，冷却期间仍可吸食，同 tick 不双重摄入。钓鱼人 F 仍为解缠，QTE 的时机与张力由房主核验；延迟补偿不会绕过按键时与当前的张力要求。反向退线、剩余线圈和结算统计同步。

这一版支持 **1 条玩家鱼对 1 名钓鱼人，另有 3 条参与抢食但不参与胜负的 NPC 鱼**。NPC 可误咬钩，真实发生的 target ID、公共提鱼/逃脱/捕获结果和线端同步；其他未接触饵仍不暴露钩真值。钓错 NPC 不结束比赛，也不能用抄网捕获 NPC。房主选择角色，加入者自动获得另一方；双方均由真人操控。原单机挑战和练习仍在标题菜单中。

0.15 的钓鱼人使用固定岸边第一人称，小鱼仍使用水下侧视。人类只能模糊看见水中轮廓，不显示对手精确体力和食物；A/D 左右移竿，W/S 调节线长。双方需更新到 0.25.6。画面和鼠标坐标在本地转换，网络继续传输同一套 2D 世界坐标；观察、两点路线、捕获及提网仍由房主判定。保留 0.14 的统计同步、双方独立 QTE、可靠状态更新和判定历史校验，房主已保存的全部玩法参数会作为房间规则；准备前可查看，房间内锁定，加入者离线设置不被覆盖。

## 如何连接

1. 双方运行同一份 0.25.6 版，进入标题的“双人联机”。
2. 房主选择“小鱼”或“钓鱼人”，点“创建房间”。默认端口为 **24712**。
3. 加入者填写房主房间中显示的 IP 和相同端口，点“加入房间”。
4. 双方点击“准备”，池塘载入后倒计时 3 秒开始。
5. 结算后双方都点“准备下一局”可再玩；“离开房间”返回单机标题。

**同一电脑测试**：打开两次游戏，一个创建，一个以 `127.0.0.1` 加入。

**两台电脑测试**：连接同一局域网，由加入者填写房主的局域网 IPv4 地址。例如 `192.168.1.10`，不能填 `127.0.0.1`。多网卡电脑可能显示多个地址，选择双方所在网络对应的地址。

首次运行若 Windows 询问网络权限，允许专用网络访问。连接超时时，先确认房主已经创建房间、双方版本及端口相同、防火墙允许该程序的 UDP 通信；公共 Wi-Fi 的设备隔离也可能阻止互连。端口被占用时，可在双方菜单中改用同一其他端口。

本轮没有账号、房间码、互联网大厅、穿透服务或专用服务器，不需要购买服务器。既往验证包含同机独立进程；本轮 P3.4 使用同一进程内两个独立 ENet peer 节点经真实 UDP 检查两种角色。尚未用第二台物理电脑验证跨机链路，也未验证公网 NAT 场景。

## 对局约定

- 人类：A/D 左右移竿、Q 下钩／补饵、W/S 收放线、F 解缠（张力 25%–55% 时空格判定）、E 进入水下观察，左键选 A 再选 B。取消/超时消耗冷却；提交后锁定直线，挥网期间暂停主动摇轮。
- 小鱼：WASD 游动、鼠标朝向、左键吸食、嘴边自动近距咬食、滚轮调吸力、右键冲刺、空格判定、E 回巢。
- 时间窗口采用房主创建房间时的单机设置，整局锁定。可在开房前从“设置 → 玩法规则”修改。
- 六分钟内人类提鱼或抄鱼出水获胜；鱼吃满并回巢，或存活到超时获胜。
- 联机菜单只停止本机输入，对局继续。切出窗口也不能暂停另一位玩家的世界。
- 断线会停止本局，不自动判任何一方获胜。当前不支持中途重连接续；返回标题重新开房即可。
- 加入者的单机时间配置不会被房主规则覆盖。离开后恢复原配置。

## 实现及验证边界

房主以 60 tick/s 执行双方指令并判定物理、进食、咬钩、张力、QTE、捕获和胜负。客户端不运行另一套结果判定；接收房主 30 次/秒的完整压缩快照，使用独立的显示世界插值鱼和钓组位置。抄网位置保留在房主实际折线上，避免在拐角之间插值造成穿越。

客户端操作使用 ENet 可靠有序通道；抄网保留同帧多个鼠标点，并携带手势编号。停止后的旧点不能重新开启手势。输入具有会话、局号、序号，旧局和重复消息不会再次执行。超过 250 毫秒收不到新操作时，房主清除持续移动、收线和抄网按住状态；持续失联约 5 秒结束连接。

快照压缩后分成小于 UDP MTU 的应用层片段，允许乱序和重复，完整收齐才更新世界。缺失片段不局部应用，后续完整快照自然替代旧快照。开始和最终结算另外可靠发送。限制消息长度、解压大小、集合长度、嵌套深度，禁用对象解码；房主不会接受客户端世界状态或 AI 开关。

QTE 按键携带客户端显示的模拟 tick 和判定编号。房主只在自己保留的最近 250 毫秒历史中查询那个判定的实际进度，不采用客户端声称的“成功”或时间值。提示音后的准备阶段不会把空格判为失败，也不会缓存到后续绿区；仅在已显示轨道的扫动阶段判定。低张力和接触目标仍须在当前世界满足，不能用旧画面绕过。仅联机增加最多 250 毫秒的结果等待；单机时长不变。超出历史窗口的迟到按键会丢弃。这是局域网原型的有限补偿，还不是面向高延迟竞技对战的完整回滚方案。

当前输入全量可靠传输，网络丢包时可能产生等待；尚未加入本机移动预测、断线重连、房主迁移、旁观者或多鱼多人。网络验证包含真实 UDP、同机双进程原生键鼠，以及针对片段丢失／乱序／重复和 QTE 200 毫秒延迟的受控检查；没有进行长时间广域网压力测试。

主要实现位于 `scripts/network_session.gd`、`network_protocol.gd`、`network_presentation.gd`。早期联机验证见 [0.12 测试报告](../test-reports/TEST-REPORT-0.12.md)，当前吸食修正见 [0.22.1 测试报告](../test-reports/TEST-REPORT-0.22.1.md)，扩大水域的抄网联机验证见 [0.21 测试报告](../test-reports/TEST-REPORT-0.21.0.md)。

技术依据：[Godot ENetMultiplayerPeer](https://docs.godotengine.org/en/stable/classes/class_enetmultiplayerpeer.html)、[传输模式与通道](https://docs.godotengine.org/en/stable/classes/class_multiplayerpeer.html)。当前使用默认通道协商；调试时发现显式 max_channels 在本机 4.7.2 运行时导致入站限流，默认设置已通过双向实测，对应 [Godot 4.7 实现](https://github.com/godotengine/godot/blob/4.7-stable/modules/enet/enet_multiplayer_peer.cpp)。
