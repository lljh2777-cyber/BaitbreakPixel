# Git 历史恢复说明

2026-09-29 为 BaitbreakPixel 首次建立 Git 仓库。此前没有 Git 提交记录；本次按版本号顺序，从本地保留的 **42 个发行包**恢复历史快照，再提交当前完整开发工程。

## 历史的含义

- 每个 `recover: v…` 提交对应一个实际保留的发行包，并有同名 `v…` 标签。提交时间是本次恢复时间，不是过去的开发时间；这些不是找回的原始开发提交。
- `.gd` 和 `.gdshader` 从 PCK 原样提取，校验包内 MD5，再记录 SHA-256；保留原始换行字节。`.gitattributes` 禁止自动改写换行，方便核验。
- `project.godot` 和主场景由 Godot 4.7.2 从二进制导出资源重建，文本格式、资源编号可能不同于原文件。
- 旧贴图由运行时导入纹理解码为 PNG，不等同于当时的原始美术文件。导入配置与脚本 UID 在验证时由编辑器重新生成。当前完整工程提交保留实际存在的原始素材与配套文件。
- 发行包未包含旧测试、设计文档、构建脚本等内容，无法准确追溯它们当时的状态。它们只在最后的当前工程提交中完整加入，没有把今天的文件冒充过去的文件。
- 各历史版本的 README、恢复清单、Git 忽略文件是本次补充的管理信息。`PLAY.txt` 和引擎声明来自对应发行目录。

## 校验和使用

42 个恢复目录均通过 Godot 4.7.2 资源重新导入及主场景实例化检查；该检查不执行游戏启动/存档逻辑，也不代表每个历史版本做过完整玩法回归。

这 42 个恢复包的发行包与源码哈希见 [history/releases.json](../../history/releases.json) 的 `releases` 数组；后续本地试玩包另记在 `local_playtests`，不属于本次恢复，字段与来源见[版本与包索引说明](RELEASES.md)。每个历史标签也有自己的 `RECOVERY-MANIFEST.json`。Git 不存放 EXE、PCK、ZIP、`.godot/` 缓存和 `artifacts/` 录制文件；原本机发行目录没有移动或删除。

日常开发使用 `main`。查看历史可以在 GitHub 选择相应标签；需要运行旧版时，建议在独立目录检出标签，避免覆盖当前工作和共用正式游戏存档。
