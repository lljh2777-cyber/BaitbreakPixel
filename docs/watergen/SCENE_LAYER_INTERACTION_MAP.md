# 沟谷倒木：场景分层与交互对应

日期：2026-10-06。依据第三轮样片 `2838165` 和当前分支的地图/绘制实现。适用于后续把自然池塘风格合并到主游戏；本轮只整理标注与接入约定。

[交互标注图](scene-layer-map/index.html) · [静态编号图](scene-layer-map/overview.svg) · [结构化规划数据](scene-layer-map/scene-plan.js)

## 先明确当前状态

**画面前后层次和玩法交互是两个独立属性。** 前景可以完全不能交互；处于中景的真实木石也可以承接缠线等玩法。

当前 A 图的地势、木石、植物仍是一张烘焙底图，只有第三轮动物已独立成层。**这套新样片现在全部是视觉，没有一个图中物体已经绑定主游戏交互。** 现有主游戏的真实地图、WG-6.2 程序化植物和游戏对象仍照旧运行。下面的金色 I 类表示“后续需要绑定的外观”，不是“现已生效的交互”。

图上的区域是便于讨论的美术范围，不是透明素材切片、碰撞范围或新地图定义。编号只用于文档，不是游戏 feature ID。结构化数据的 `feature_id` 均为空，`annotation_geometry_is_authoritative` 为 false，不能作为 `MapDefinition` 导入。

## “可交互”具体指什么

核对了 [当前生成地图](../../scripts/maps/generation/generated_pond_v1.gd)、[固定地图](../../scripts/maps/pond_v2_map.gd)、[World](../../scripts/world_simulation.gd)、[MapContext](../../scripts/maps/map_context.gd) 与 [抄网模拟](../../scripts/net_simulation.gd)。当前木/石/草的既有行为如下，未来一律读取实际目标能力，不由新外观重新声明：

| 既有行为 | 木头 / 大石 | 交互草 |
|---|---|---|
| 阻止玩家鱼穿过 | **否**，当前 `fish_passable=true`；玩家移动仍由真实水域及原线长约束决定 | **否** |
| 缠线目标 `rope_anchor` | 是，沿原 polygon 判定 | 是，沿原目标判定 |
| 接触淡化 `contact_fade` | 是，连接木按既有组同步淡化 | 是，保留原目标淡化 |
| 抄网阻挡 `net_blocking` | 是 | 否 |
| 束草 `grass_binding` | 否 | 是，原草丛随现有鱼线变形 |
| 植被减速 | 不由木石外观决定 | 仍由既有 `vegetation_drag_zones` 决定，不按新草叶面积扩展 |
| 其他既有能力 | 保留 `npc_spawn_blocking`、`fish_occluding`、`shore_visible` 等原值 | 同样保留原值，不为装饰授予能力 |

“能缠线/挡抄网”不能描述成“玩家鱼撞上就过不去”。本轮不调整 NPC、遮蔽或抄网规则。

## 从画面到真实对象的绑定

1. **先读已安装地图，再安排外观。** 使用不可变的公开 `MapContext` 与 `MapPresentation`；保留 `feature_id`、`compatibility_index`、`polygon`、`bounds`、`fade_group_id` 和能力。图片不能反向生成真实 target。
2. **I01/I02/I03 是外观角色，不是预定地图 ID。** 在每张实际地图中找到对应 kind 的已有对象再实例化外观；绑定记录才能填入其真实 ID。主图中的一根长倒木不能把多段不相连的目标拼成新障碍，也不能挪动真实地图来贴合 A 图。
3. **保持可用轮廓与原接触边界一致。** 木纹、石面和草叶围绕原形状制作。装饰性的苔藓小突起不能暗示额外可缠线面积；重要交互轮廓不能被不透明装饰掩埋。
4. **附着物引用宿主，不继承宿主的交互能力。** D03/E02 可保留公开宿主 ID 和表面偏移，只用于视觉变换、裁剪和透明度；不创建新目标，不修改现有目标序号或淡化组。
5. **找不到匹配时改变外观。** 重排或重做木石/草的图形；仍想保留的大形体移到明显低对比的远景，或省略。不能留下“看起来可缠线，实际无目标”的高对比主物体。

[MapPresentation](../../scripts/maps/map_presentation.gd) 已带 `feature_id`、`target_index`、实际轮廓和淡化组。现有 [WatergenPublicAdapter](../../scripts/watergen/watergen_public_adapter.gd) 输出了公开轮廓、范围、legacy target index、淡化组和保护区，**当前并未导出完整 feature ID/能力表**；后续绑定通过公开 MapContext/Presentation 获取，不能误以为 adapter 已具备这些字段。本轮没有更改 adapter。

## 地势和构图的特殊处理

当前生成池塘的实际基线为 1280×480，`water=Rect2(8,68,1264,363)`、`floor_y=433`（见 [生成约束](../../scripts/maps/generation/generated_pond_profile.gd)）。A 图的两侧高坡和低沟是美术深度，**不是这个真实边界的新形状**。合并时每局读取实际 context，不能把这组示例数值写死进新装饰系统。

- 后方高坡属于背景池岸，不剥夺前方可游水域；近处土沿收低到真实边缘附近，避免角色看起来穿过实心土坡。
- 巢穴和出生点附近必须露出清晰空间。A 图左下目前较密，不能直接铺到实际 home/spawn 上。
- 按公开候选饵位统一留出可读空间；不能根据哪一个饵暗藏钩来改变植物、光束或动物。
- 图中 `Rect2(320,77,679,230)` 只代表 A 构图的中央留白参考，不是安全区全集或鱼可游区。正式合并还要检查实际巢穴、出生点、全部公开候选饵位、抄网活动范围、所有镜头与 HUD。
- 地毯藻、沟底低草与坡脚宽叶草可以建立生态关系，但关联的是**公开表面信息或独立美术挂点**，不会回写地图地形。

## 绘制接入顺序

不重新发明统一的 Z 排序。[PondView](../../scripts/pond_view.gd) 已对 NPC、缠线鱼、食物和鱼线做前后穿插，草也有 `back` 标记。

| 拟插入位置 | 新内容 | 保留事项 |
|---|---|---|
| 现有 `Scenery.background` 一带，NPC/玩法对象之前 | B01–B03、明显后退的坡岸、E03 鱼群 | 低对比，不能抹掉角色与细线 |
| 现有底层/背景植物通道，按遮挡关系安排 | D01/D02、E01 小虾 | 不改变原鱼/饵/线的前后分支；不能盖住识别对象 |
| 原 props / plants 绘制位置 | 已绑定的 I01–I03 | 原目标位置、轮廓、`back`、`target_opacity`、束草与淡化组保持 |
| 紧随各自宿主 | D03 苔藻、E02 蜗牛 | 使用宿主同一淡化值；未绑定宿主则省略 |
| 现有 `Scenery.foreground` 一带 | F01 低矮近景框景 | 仍早于前方食物/鱼线/玩家；对更早绘制的 NPC/缠线通道裁除遮挡 |
| 现有 gameplay 与屏幕 UI 通道 | 原玩家、NPC、食物、线、网、巢穴提示、QTE、HUD | 使用既有观察结果与白名单，不用美术图替代，不读取额外隐藏状态 |

前景装饰不能因为“前景”二字就放到所有玩法对象之后。鱼线绕木、缠草及饵的已有穿插关系比装饰层名优先。

## 后续合并的工作单

1. 按规划的 `asset` 名拆出带透明度的背景、装饰、宿主外观和近景资源；去掉原烘焙图中的重复物体。当前没有这些独立切片。
2. 先接纯背景/低矮装饰，按真实地图与公开保护区布置，检查巢穴及全部镜头。
3. 再逐一替换现有木、石、草的外观；在真实 target 上验证缠线、接触淡化、草束变形和抄网可读性，不增加能力。
4. 让苔藻/蜗牛跟随宿主，并将动物美术坐标替换成公开表面挂点。本地视觉时间和种子独立于权威 RNG；不创建可同步动物状态。
5. 同种子对比合并前后的地图对象、边界、能力、锚点与玩法结果；再做真实玩家/食物/线/网/QTE、鱼方隐藏钩边界和联机显示的回归。当前固定识别样本不能替代这一步。
