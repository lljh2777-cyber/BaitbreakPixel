使用本机现有 Godot 4.7.2 与 `D:\python\python.exe`，无需安装依赖。启动器支持 `-Godot` 指定引擎路径。

- 左上输入框：输入真实地图种子，回车或点“生成”。

“真实地形”模式显示当前地图的木石和交互草；“真实地形与群落”在其上叠加新植物，隐藏已有远景装饰，便于检查植物是否贴着正确表面生长。地图种子改变地形，视觉种子只改变植物外观与分布细节。

## 群落与层级

| 生境 | 新植物 | 关联方式 |
|---|---|---|
| 石面 | 苔藻 | 挂点来自真实多边形上表面，苔藻像素限制在原石面内部 |
| 木枝 | 苔藻、附生细叶、下垂丝状藻 | 取真实上/下表面；整木淡出时使用相同透明度 |
| 交互草周边 | 矮草、丝状藻 | 沿现有草丛两侧与真实底部生长，不增加交互目标 |
| 木石间空隙 | 地毯藻、矮草、宽叶草 | 从真实木石投影之间找空隙，群落根部落在真实池底 |

各类共享群落布局，同时使用各自命名的视觉随机源。池底左段较密、中央较稀、右段适中；整体密度可切换。整株范围避开巢穴、出生、候选饵点及中央主要视野。植物不是可吃实体，不会缠线、阻挡抄网或改变移动阻力。

宽叶草与矮草位于演员后方，苔藻在现有木石表面；没有新增覆盖 HUD 的前景层。新植物以一张图集绘制，不为每株建立 Node，轻微摆动只用显式视觉时间。

& 'D:\python\python.exe' -X utf8 'E:\Fish_catches_people\aquatic_system\BaitbreakPixel-watergen-v2\tools\watergen\run_wg62.py' --godot 'E:\chrome下载\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe'

默认执行导入、群落契约、原生四模式捕获和真实游戏视图检查。`--mode headless` 只跑契约，`--mode native` 跑两类原生检查，`--mode preview` 打开交互预览，`--skip-import` 跳过已完成的导入。

结果写入新的 `artifacts/watergen/wg62-<时间>`，已有目录拒绝覆盖。用户数据目录隔离、进程限时，出现引擎错误或缺少完成标记时运行器会判失败。原始截图和 JSON 在本机产物目录；代表截图与简洁验证记录随提交保存。没有整库文件哈希清单。

当前阶段等待确认植物密度、贴合程度与可辨识度。正式游戏入口尚未接入这批群落，没有推进动物或真实生态行为。
