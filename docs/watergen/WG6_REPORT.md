# WG-6.0 + WG-6.1 交付报告

日期：2026-10-04。阶段状态：**WAITING_FOR_REVIEW**。

本轮交付四构图的视觉地势独立预览：缓坡、浅丘、沉积沟和石质台地。开发基于 [e333c90 / 0.25.6](WG6_BASELINE.md)，完成 fetch 后确认 dev 没有新增提交。正式游戏版本、生产绘制入口、玩法与试玩包均未改动。

## 实现

`water_visual_terrain.gd` 只产出字典、数组和数值组成的 VisualTerrainPlan。白名单 Profile 决定地势类型、起伏幅度、丘/沟数量、中央留白和岸侧偏向；种子确定位置、宽高、曲率与纹理。先确定左右岸、中央沟和低丘的大构图，再生成石台。局部随机源使用 `terrain` 命名子流，与原有光束、植物及未来生态子流隔离。

`water_terrain_baker.gd` 在 CPU 上烘焙远景与床面：坡缘采用离散透明度和像素覆盖，坡面带低对比沉积色带；石台边缘比真实交互木石弱。中央保持低起伏，近侧小丘仍在演员与真实木石后面，没有新增前景遮挡通道。

预览侧的 `terrain_preview_cache.gd` 复用原 DynamicGenerator、DynamicBaker 与两套 LRU 缓存，仅替换远景、床面像素。水体、表层、既有植物层、前景及动画图集保持原样。生产 `pond_view.gd` 和水域适配器没有引用新模块。

交互预览支持四构图、四种显示模式、五镜头、平移、暂停和旧静态可读性样本。复用 WG-5 RGB 材质以对照现有生成环境；所有真实木石与草叶参考保留尺寸、位置、alpha、目标成员。Legacy 对照使用原素材。因旧独立预览早于生成水域接入，新增一个仅供 WG-6 使用的 legacy 子类，显式提供当前 Scenery 要求的 `generated_water_active = false`，没有改动共用 Scenery 或旧预览文件。

## 实测成本与限制

设备：Windows，Godot 4.7.2 `ed1daf0bf`，OpenGL Compatibility，AMD Radeon(TM) Graphics。以下每项是本机一次冷准备样本，包含原有环境 + 新地势的计划、CPU 烘焙与纹理上传 API 调用，不含引擎启动或木石/草叶材质准备。

| 构图 | 计划 | 烘焙 | 上传 API | 合计 |
|---|---:|---:|---:|---:|
| 蕨叶庭 | 12.9 ms | 1947.2 ms | 3.7 ms | 1963.8 ms |
| 长叶湾 | 20.9 ms | 2254.0 ms | 4.3 ms | 2279.1 ms |
| 浮叶荫 | 11.1 ms | 2404.9 ms | 4.6 ms | 2420.6 ms |
| 垂根岸 | 11.7 ms | 2388.3 ms | 4.3 ms | 2404.3 ms |

首次或缓存未命中的切换会同步等待约 2.0–2.4 秒，独立原型目前保留此限制；正式接入前需要确定预热/准备流程。命中缓存时不烘焙、不上传；平移不触发生成。不是“整个游戏不卡顿”的承诺。

240 帧平移中，现有 Canvas 提交绘制命令的 CPU 中位数 431 µs、p95 632 µs。它不包含完整游戏逻辑，也不是 GPU 时长、FPS 或实战帧率指标。每个生成 bundle 仍是六张环境纹理和一张动画图集，缓存最多两套；对照预览另按需保留一套 Legacy 素材及木石草叶参考。日志的累计 147 次 Texture 创建代表 21 次准备全程累计，不是同时驻留数。
