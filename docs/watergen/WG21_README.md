## 视觉设计

一个 profile 内，由 `visual_seed % 4` 选择植被组合，并用独立命名随机流决定左右优势、群落位置、光域开口、尺寸和相位。相同组合的不同 seed 仍有不同布局，不依赖世界随机数。

| Seed | 组合 | 主要差异 |
|---|---|---|
| 713284 | 蕨叶庭 | 青绿基调、片状蕨叶、层次更清晰的两侧草丛 |
| 2649 | 长叶湾 | 更高的弯曲带状叶、纵向簇群、略偏绿水色 |
| 42 | 浮叶荫 | 较大的上缘浮叶、较低远景、较宽的开阔水体 |
| 731 | 垂根岸 | 更长、更宽的岸缘垂根，偏蓝水色与不对称草丛 |

先调整大块构图和植被轮廓，再补低对比床面落叶。没有增加假木石、鱼影、食物状金色闪点或模拟水流方向的漂移。原木石、交互草、食物和夹具的画法保持原样。水体与光束仍静态烘焙；新版水色只有小幅色相变化，没有浓雾、夜景或全屏后处理。

默认共 18 处装饰动态：6 株远景草、8 株中景草、2 株前景草、2 组上缘垂根。草从底端生长，垂根从顶端生长，各自锚点固定；最大位移分别为 4 / 3 / 3 / 3 px，周期与相位错开。显式时间仍可暂停、seek 和重复采样。物理力、碰撞和交互目标不随它们变化。

每个动态对象只烘焙一张小图，18 张小图合入一张带透明间隔的图集上传，最多保留两个 bundle。绘制时先排除视口外的对象，再根据弯曲曲线的整数位移阈值合并相邻像素行，每个可见对象最多 5 次绘制；不再逐行重复计算正弦，也不逐帧创建图像或纹理。测试将合并结果与逐像素行定义比较，并检查图集区域与原小图逐字节一致，避免用精度换性能。

## 基线和版本

- 本轮代码基线为 `77732863da30e02d87e3fa048ab94a031d65beda`，底层游戏冻结在 `4e8a7b9011b65e53e1971cf3ddcba38880fbd6c8`（0.24.6）。
- 开始时 fetch 发现上游 `f32d2dc250e2fcb468d9f404120dc671b22522c9` 已包含 NPC 鱼/0.25.0，涉及 authority、协议、View 和素材函数；本轮没有合入。固定地图及旧水域画家本身在两者之间无差异。
- 这使视觉前后比较使用同一套既有几何与玩法基线。对 0.25.0 的生产适配及兼容性没有测试，也没有批准。
- WG-2.0 的生成、烘焙语义和 profile 保留用于对照；WG-2.1 使用新版本、栅格标识、profile 摘要和缓存键。WG-1 代码不变。共享 Frame 分段优化必须保持旧画面像素一致。

```powershell
& D:\python\python.exe tools/watergen/run_wg2.py --godot 'E:\chrome下载\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe' --mode all --clip --run-id wg21-final-02 --timeout 240
```

使用新 run-id 复跑；已有产物不覆盖。`--baseline` 运行旧 WG-2.0，`--test-seconds 1` 是 smoke，不能冒充 60 秒验收。`--clip` 输出 100 张 1280×480 帧，显式时间 0–9.9 秒，可用 ffmpeg 编成 10 fps 视频；实际预览随显示帧率绘制。视频只是便于查看，精确像素验证使用原始 PNG/RGBA。

自动验证包括输入边界、四种子构图差异、命名随机流隔离、18 处动态上/下端锚定、像素行合并等价、确定性、原生边缘/定位、前后切换、20 次切 seed、60 秒运行和公开地图字节不变。可读性与美术是否满意仍需用户看样片；本轮停止于视觉评审，继续遵守暂不接入试玩的决定。
