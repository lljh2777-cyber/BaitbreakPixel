# P3.4 · 上钩开局与 NPC 拉起修正 0.25.4

2026-10-03；`feature/dev`；基线 `b739fdaf477461cdbbdcf97224887b0d27473bc1`，完整保留用户刚发布的 0.25.3 Windows 文档。针对“玩家 QTE/缠线偶尔刚开始就失败、NPC 拉起太拖沓”的人工反馈，只修本阶段。源码版本 0.25.4；本轮仅提交推送，不生成 ZIP/PCK/EXE/Release。公开 Windows 包仍为 0.25.3，不包含本次修正。

## 已复现的原因

1. **准备阶段按键被判失败**：HUD 在默认 0.4 s 提示阶段不显示轨道或绿区，但原模拟仍接受空格并立即判失败。第一次 tick 即可在年龄 0.0167 s 复现；入口失败只是挂牢，并不是比赛输掉。
2. **缠线准入早于真实移动**：鱼在障碍接触边界按空格，原逻辑先开缠线，再计算移动/鱼线拉力；单帧约 0.47 px 的正常拉拽就可能离开边界，导致 `qte_age=0.0` 已失败，玩家看不到可操作的一帧。
3. **暂停/失焦恢复的空格被重复使用**：原生窗口中用空格激活“继续”，同一事件又进入游戏 QTE。即使已进入可见轨道，这也能造成意外失败。
4. 修前两项在不可变 **0.25.2 `cfbdd9e` 与 0.25.3 `a6e8656`** 上结果完全一致：新增 46 项玩家回归均为 22 通过 / 24 预期失败，无脚本错误。没有发现 NPC 误写玩家 QTE 年龄、目标所有权或旧计时器泄漏。见[0.25.2 负向证明](data/hook-feel-0254/baseline-0252.log)、[0.25.3 负向证明](data/hook-feel-0254/baseline-0253.log)及[最小原始探针](data/hook-feel-0254/original-first-frame-probe.txt)。

100 个固定种子的无输入/旧状态污染检查中，入口均重置计时并保留完整机会，没有无输入刚开始就输掉比赛的复现。默认 0.4+2.0 s 到期在 60 Hz 浮点累积下为第 145 tick，即 2.4167 s。真正的回合倒计时、已提交抄网命中和岸边提鱼仍保留各自的终局原因；没有用本修正屏蔽它们。若人工看到的是整个比赛立即结算，仍需依据画面的结算原因进一步定位，不能用这几条技能误判修复代替所有可能原因。

## 修正范围

- 入口、松线、缠线、双方发力、解缠均在**已显示目标的扫动阶段**才接受判定。准备阶段空格被消费，不缓存在绿区；最后一个准备画面的输入也不会因 tick 跨过边界被误判。原成功区宽度、扫动时间、超时、QTE RNG 与成功/失败效果不变
- 缠线在当帧移动、拉力和抄网结果后检查真实接触；同一空格只开启，不同时判定。离开障碍明确显示“离开障碍 · 缠线中断”；准备期接触或松线条件消失不记一次技能失败，已经进入扫动的中断仍记失败，保持接触约束和重试冷却
- 菜单、失焦、重开后的空格须先释放，再形成新游戏按键；既有移动和抄网输入机制不改
- 独立复审发现同一网络批次中的准备按键会吞掉后续有效按键，现允许后续可见按键替换准备按键；**第一个可见判定仍拥有本次判断**，不会跳过可见失误挑选后来的绿区。时间只使用房主已验证历史，编号/历史界限/重复包/伪造时间守卫不放宽
- 网络 exact-build 0.25.4；authority schema15、FoodProfile guard3、鱼端 NPC guard2、钓鱼人 guard4 不改。没有新增快照字段或泄露 NPC 私有状态

## NPC 实际收近时间

旧测试把 NPC 放到岸边再测 lift，只证明了提鱼路径，未覆盖漫长的水中收近。新测量从真实嘴部接触开始，之后不挪动 NPC、不强改绳长、不跳过动画。

仅 `npc_hook.gd` 的向内 spool 与物理拉力采用 **1.8 倍**系数，仍由原执行器逐 tick 积分；放线速度、挣扎、松口条件、持续高张力阈值、0.65 s 岸边确认和 1.05 s 提鱼动画不变。玩家自身控线、NPC 生态游动、自动 Bite 10 px/0.80 s/4–6–8、抢食和补饵、地图均未调参。

沿用先前25个种子64401–64425、原P2 Mixed鱼策略、原AnglerBrain和默认规则，四模式共100场；另有独立4×4 pilot。所有100场自然终局，源码指纹一致。这里刻意重用旧种子作**源码配对回归**，不是新的独立留出样本或真人胜率；不会以50%胜率作调参目标。

| 模式 | 0.25.3→0.25.4鱼获胜 | 0.25.4平均食物 | 0.25.4平均局时 |
|---|---|---:|---:|
| NoNPC | 10/25→10/25 | 51.198 | 71.541 s |

加快处理也缩短玩家可利用的机会，固定策略的鱼胜率从48%降到28%，这是需人工判断的取舍，不能只报提速而隐藏输局。当前源码还包含玩家QTE修正，因此不把这100场当作严格的单参数因果试验。NoNPC/Passive的食物/局时/Hook/胜负与旧版相同，但seed64412的fish_total由5变4；这是准备/中断统计变化，不能声称完整记录字节相同。Foraging旧/新记录完全相同，当前NoNPC与Passive仍逐种子相同。

## 测试修正与限制

- 原发力/解缠测试曾用隐藏提示期的按键作“失败”夹具，现移到刚显示轨道但仍在绿区外的位置；原失败、脱力、保留线圈等断言完整保留，另加准备期不失败断言
- 原 NPC 强制零绳长断线夹具位于中水，提速后会先到岸而捕获。保留原断线断言，把该夹具在**接触之前**移至深水；另外用真正 W/S/移竿与原阈值验证可操作的断线和逃脱，不把误捕当断线通过
- 第一次新增原生长按后鼠标恢复检查错误地以 640×360 逻辑坐标点击 2× 原生窗口，点偏“继续”；改为经窗口变换后的真实输入坐标，保留原状态断言。正式结果另由完整重跑给出
- 渲染使用真实 Linux 云端 X11、Godot 4.7.2 official、Compatibility/Mesa 软件渲染、Dummy 音频；不代表 Windows 导出包、真实声卡、公网 NAT 或跨物理设备验证
- 实际 ENet 指同进程两个独立 UDP peer 节点，不描述成跨设备测试。自动策略不会成熟的玩家 QTE 技巧；自动/原生通过不关闭人工门，也不替代用户对节奏的判断

## 人工复测门：仍为 P3.4

1. 上钩听到提示就按/长按空格：提示阶段应继续；释放后看到浮漂进入原绿区再按，仍能吐钩。可见阶段按错仍失败但仅挂牢，不应凭空结算整局
2. 接触草木石按空格缠线，继续游动抗拉；保持接触才能成功，离开应明确提示中断，不出现刚开就“判定失败”
3. 入口、缠线或发力中 Esc 暂停/切出再切回，用空格继续；释放后再按，检查没有旧按键误判。再重开、再次上钩重复
4. 钓鱼人分别从浅水/深水处理 NPC，用 W/S 比较收近节奏；试持续 S 松口，试 W 同时向远离目标方向移竿制造持续高张力断线。仍需保留处理成本和玩家吃饵机会
5. 钓错 NPC 后比赛继续、钓组可重新部署、约8 s补充新 ID；玩家在 NPC 占线时继续吃饵/回巢
6. 两端均用0.25.4交换鱼/钓鱼人角色，确认 QTE、缠线、目标、捕获/逃脱一致
