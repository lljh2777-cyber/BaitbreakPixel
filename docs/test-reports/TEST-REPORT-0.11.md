# 0.11 最小必要重构验证

日期：2026-09-26。Windows / Godot 4.7.2 / Compatibility OpenGL。

## 本次变更

世界模拟从本机应用层抽出，双方通过同一个 tick 提交操作；本机角色不再决定世界规则和绝对胜者。现有键鼠、鱼 AI、钓鱼人自动策略均转为指令来源。钓组执行器保留原有惯性、收放线及抄网规则。

增加版本化世界快照，覆盖全部可变模拟和钓组字段、随机状态、QTE 序号及抄网路线；复制和恢复不共享活引用，恢复不会重复发出结果或音效。固定地图以 map_id 标识。新局配置不继承前一局状态，单机保存的参数由应用层显式传入。

本次保持单机两种挑战与自由练习。内部共享世界入口用于验证不同本机视角、菜单与世界模拟相互独立；尚未增加房间或网络传输。

架构检查覆盖：

- 世界可独立于场景树、菜单、音效和键鼠节点运行。
- 同一个 tick 同时处理双方操作，外部鱼的吸力不会被 AI 默认值覆盖。
- 快照字段表覆盖全部可变世界和钓组字段，新局不遗留惯性、规则和效果状态。
- 下钩中、抄网折线执行中、入口 QTE、成功缠线动画、捕获提网、游离饵与已计分颗粒均可恢复；恢复后提交相同指令，逐 tick 快照一致。
- 嵌套颗粒和 PackedVector2Array 不共享引用，输入快照后续修改也不改变已恢复的世界。
- 格式版本不符、缺失字段或非有限数值被拒绝；拒绝不会部分覆盖状态。
- QTE 随机状态和序号恢复正确，不重复播放音效或写入胜场。
- 两个相反角色的本机视角在同一规则、种子及双方操作下得到相同世界；帮助菜单不会暂停共同模拟，时间设置及本机重开不会修改共同规则。
- 同一绝对胜者在双方展示相反结果，重复结算不会多记胜场；超时胜者取决于规则。

原生抄网检查使用实际 Godot 窗口和输入事件。键鼠先进入指令缓存，下一 tick 按原顺序执行，验证水中起点、同帧闭环拐点、网口回放、E／左键取消、暂停后的释放要求。松键取消在该 tick 的扫网／捕获计算前执行，最多等待约 16.7 毫秒；原 0.10.2 中“在输入事件回调直接修改世界”的断言已替换。已查看 following-loop-v011.png，确认实际网口位于折线的正确线段。
