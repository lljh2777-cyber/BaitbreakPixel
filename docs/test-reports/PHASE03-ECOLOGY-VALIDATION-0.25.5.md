## 结论与本轮改动

**本轮未发现需要重新调节生态参数的机制性问题，保留0.25.4已实现的玩法和NPC收近速度。** 四种生态状态确实产生不同食物竞争、占线机会和终局分布，但效果随模式/策略变化，当前证据不支持一刀切加强或削弱。交付的是可复现的P3.5验证、回归和最终人工清单，**不是Phase 3已由用户关闭**。

默认3条NPC会真抢食，也会被钓错；玩家能在占线期间真实吃到食物。另一方面，挑战策略表现差异大，个别回合近一半时间在处理NPC，必须保留给人工判断。没有为了漂亮胜率修改默认食物目标、密度、饥饿或玩家技能风险。

- 新增 2/3/4 条正常密度的集成回归，覆盖饥饿开关、两规则模式、挑战/练习、暂停、回放、双角色裁剪和真实捕获补鱼
- 新增四种生态状态 × 十二种玩法/策略组合的预声明、完整真实 tick 统计，严格区分 pilot、留出与旧版本回归
- 增加饥饿/行为暴露、供给准入、NPC 占线期间玩家摄食、成功补鱼和未达标/未终局记录；这些仅在离线工具中，不进入玩家 HUD 或网络；authority schema15、FoodProfile guard3、鱼端 NPC guard2、钓鱼人 guard4不变
- 追加统计完整性、整簇重采样、分片合并和无损可读证据检查
- 保留既有玩法参数；运行时代码仅更新版本/菜单/日志标记，地图、玩家 QTE、摄食/钩判定和 NPC 行为实现不重写

### 饥饿、社会反应和钓错鱼成本

- 完整生态300场共有220次NPC附着＝164次捕获＋15次逃脱＋0次断线＋41次在玩家终局时仍占线；164次捕获＝125次已成功补鱼＋39次因玩家先终局仍待补鱼。计数全部闭合；终局后停止生态/补鱼是原规则
- 15次自然逃脱均发生在对战挑战；没有自然断线样本，其他模式不冒充逃脱覆盖。受控W/S和持续高张力断线、暂停/终局停止、真实提鱼和新ID替换另外通过
- 93场玩家在NPC占线时实际摄入食物，累计496.5点；NPC占线总计1,281.333秒，即每个完整生态回合平均4.271秒、合并时长占比10.42%。这是按回合/暴露统计，不除以220冒充已完成单次处理均时，因为有41个未结束事件
- 保留高压力样本：73610对战挑战SuckOnly，41.9秒回合有19.4秒处理NPC（46.30%，1次捕获＋1次逃脱），玩家期间吃4.95点，最终被抄网；73601同分层5次捕获累计占线40.967秒，回合134.867秒，最终仍被抄网。这些值得人工判断，不只报平均数
- 按活跃NPC时间加权，完整生态平均饱食37.16，临界饱食暴露34.91%，极饿19.65%；行为时间中犹豫8.83%、逃开8.38%、争食8.06%、FEED7.86%。说明饥饿和社会反应确实发生，但时长受生存/捕获/补鱼选择影响，不是理想生态目标值或人类情绪判断

### 资源压力的不利片段

最长全场无可食物片段为 **21.383秒**：种子73620、对战挑战BiteOnly、Foraging；该场全部空食物tick的补给准入为0，玩家最终因提鱼失败。完整Hookable最长19.233秒出现在73624生存挑战BiteOnly，玩家已吃72.3点但仍被提起。这些片段保留，不说“永不缺食”或把达标直接当胜利。

单场累计具有补给准入的空食物时间最大2.15秒（73623，对战挑战SuckOnly，Foraging）。这不是未来所有实时状态的上限，更不是结构见证7.05秒的替代口径。结构可达、实际实时找食物/逃脱、真人感觉是三种不同检查。

所有详细数值、逐层六组配对比较、原始行、运行命令和源码哈希见[证据索引](data/ecology-0255/README.md)。原始行按十二分层保存为未压缩 JSONL，仅把完全相同的规则放入一个共享文件，保留完整统计字段、数值精度和原行次序；附带校验和与无损重建工具，可重建原数据后重新分析。没有以压缩块隐藏原日志，也不只保留有利回合。

### 指标不能过度解释

- `npc_active_seconds` 是多条活鱼时间总和，可超过回合秒数；NPC 饥饿统计使用它作分母
- `player_food_while_npc_hooked` 是本 tick 开始时 NPC 已占线的 tick 内新增真实摄食，只证明机会被使用，不证明全部摄食由 NPC 因果造成
- `npc_social_reaction_entries` 是 HESITATE/FLEE 状态入口，不是独立线索次数；持续社会线索仍由原锁存机制处理
- `player_npc_food_contests` 只统计成功 NPC Bite 中有选中颗粒落在玩家嘴范围内的事件，不等同于全部吸食竞争或 COMPETE 时长
- `npc_target_switches` 包含从无目标首次获取；`lifecycle_events` 是新饵 ID 数，重挂与投放可能分配两次，不等于独立食物批次数
- 无食物/准入暴露采用 tick 前状态。准入仅对应生产 `_step_supply` 顶层条件；某个被占用饵位仍可等待。已有玩家上钩/抄网阻断区间不包装成永久死锁
- 新玩家饱食均值是 tick 前采样；保留的 legacy RoundStats 是 tick 后采样，不强行声称两个量逐字相同
- 缺少自然逃脱/断线等事件的分层明确保留0与支持数；机制由受控动作验证，不能用样本零推断总体频率零

## Phase 3 最终人工试玩门（未关闭）

双方使用 0.25.5 源码；默认规则先试玩，避免以旧自定义设置误判版本变化。建议鱼/钓鱼人各2–3局，并穿插一局练习：

1. **鱼的主体性与抢食**：能一直辨认自己的鱼；默认三条会真抢食，但不会长期遮挡/堵路。分别接近三类饵，判断“需要快一点”还是“只能干等、很烦”
2. **饥饿与补給**：观察 NPC 吃饱后是否有休息、饥饿时是否重新争食；即使某团被吃光，转场/补饵后仍有达标和回巢机会。记录让你持续找不到食物的场景及当时是否上钩/抄网
3. **社会线索**：靠近、犹豫、逃开能否自然看懂；同一种动作不应总能推断有钩/无钩；玩家仍需要自己判断
4. **钓错目标的机会**：遇到 NPC 中钩，鱼玩家趁机吃饵或回巢；钓鱼人用 W/S 处理浅/深位置，确认缩短后的节奏有成本但不拖沓，处理完能 Q 重新部署
5. **补鱼与胜负**：钓错 NPC 后比赛继续、玩家分数不凭空增加；约8秒后有新鱼加入。NPC 不作为抄网胜负目标；玩家仍正常可能被抄网或提鱼
6. **既有玩家风险**：入口/缠线/发力的提示准备阶段空格不应误失败；可见阶段按错仍失败，离开障碍仍中断。试暂停、切出恢复与重开后重复操作，确保没有旧空格误判
7. **双端与总体验**：交换角色试玩，比较目标/线端/捕获/逃脱/食物变化。尤其判断 NPC 误钩是否太频繁、钓鱼人是否只顾处理 NPC、玩家是否仍是比赛核心

反馈最有用的是：角色、挑战或练习、默认或自定义规则、哪个片段太慢/太挤/太难，以及能否重复。只有用户明确认可整体节奏后才关闭 Phase 3；本报告与自动统计本身不关闭该门。
